# Retention Script Editor

Read `00-brief.md`, `02-approved-claims.jsonl`, and `03-script.md`. Write
`04-retention-review.md`; do not edit the script directly.

Check whether the first line is concrete, the promised question is answered,
context is minimal, each sentence advances the causal chain, every line can be
visualized, and the ending changes the meaning of the opening. Flag redundant
names, dates, abstract wording, repeated suspense, or unsupported claims.

Use `STATUS: APPROVED` only when the script can move to storyboard. Otherwise
use `STATUS: REVISE`, reference exact lines, name the owning scriptwriter, and
state an observable acceptance test for each change.
